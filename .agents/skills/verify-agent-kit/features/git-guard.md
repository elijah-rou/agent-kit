# Git guard

Before Claude Code runs a shell command through Bash, Monitor, or PowerShell, agent-kit's PreToolUse hook checks it against the git policy Pi's `git-interceptor` also applies. Any session that skips git hooks (`--no-verify`, `git commit -n` or `git am -n`, an override or `git config` change of `core.hooksPath` or a `hook.*` key, a hook manager's skip variable (`HUSKY`, `HUSKY_SKIP_HOOKS`, `SKIP`, `PRE_COMMIT_ALLOW_NO_CONFIG`, `LEFTHOOK`, `LEFTHOOK_EXCLUDE`, `OVERCOMMIT_DISABLE`) in a command that runs git, set on the git command, on a program the guard follows into that runs it (`sh -c`, `eval`, `env`, a here document fed to a shell, and the other wrappers), as a standalone assignment, through `export`, `declare`, `typeset`, `local`, or `readonly`, or with PowerShell's `$env:NAME =`) gets a refusal naming what to do instead, and so does a subagent that pushes, pulls, merges, rebases, cherry-picks, reverts, applies a patch, tags, or runs `gh pr merge`, unless it runs as an `autopilot-owner`. The main session may publish. An event or command the hook cannot read is refused rather than let through, and the guard also refuses some commands it need not, mostly mentions of a refused command in a quoted message or search; each such refusal names how to rephrase (see Gotchas).

## Sub-features

- `main-push` lets the main session publish.
- `main-no-verify` and `main-commit-n` refuse skipping hooks in the main session, and so do `main-heredoc-no-verify` (a flag after a here document in a substitution) and `main-redirected-commit-n` (a redirection before git).
- `main-hooks-path` refuses `git config core.hooksPath <dir>` with a reason that sends it to the user.
- `main-mention` refuses a commit message that mentions `--no-verify` with a reason that says it may be a mention and names `git commit -F <file>`; `main-commit-file` lets `git commit -F <file>` through.
- `main-unreadable` refuses a command with an unclosed quote.
- `main-arithmetic` lets `$(( 1 << 2 ))` through, and `subagent-arithmetic-subshell` refuses `$((git push ...) 2>&1)`, which is a substitution holding a subshell.
- `main-hook-key-override` and `main-hook-key-write` refuse a `-c hook.*` override and a `git config hook.*` write; `main-am-n` refuses `git am -n`.
- `main-heredoc-to-sh` reads a here document piped through `cat` into `sh` as commands; `subagent-printf-to-sh` refuses `printf ... | sh` as unreadable; `main-script-reads-data` lets data piped into `sh script.sh` through.
- `subagent-eval-dash-c` refuses `eval git -C repo push`, and `subagent-case-comment` refuses a push in a case clause after a `#` comment holding an apostrophe.
- `main-remove-section` refuses `git config remove-section hook.lint`; `main-husky-skip` and `main-exported-skip` refuse `HUSKY=0` and an exported `SKIP=` on a git command, and `main-skip-without-git` lets `SKIP=lint pre-commit run` through.
- `subagent-pwsh-ambiguous` refuses `pwsh -in -c ...`, whose `-in` could be two options; `subagent-quote-in-parameter` refuses a single quote holding `}` or `"` inside a double-quoted `${...}`, which bash and zsh read differently.
- `main-skip-into-sh` refuses `HUSKY=0 sh -c 'git commit ...'`, and `main-powershell-env-skip` refuses PowerShell's `$env:HUSKY = '0'` before a git command.
- `subagent-pwsh-value-names-command` refuses `pwsh -wd /c -c ...`, whose `/c` is a value that also names -Command, and `main-skip-into-find-exec` refuses `HUSKY=0 find ... -exec sh -c 'git commit ...'`.
- `subagent-powershell-capture` refuses `$out = git push ...` in PowerShell, `subagent-subtree-prefix` refuses `git subtree -P dist push ...`, and `main-unset-hooks-path` refuses `git config --unset core.hooksPath`.
- `main-case-patterns` lets case patterns such as `*A*)` through, and `subagent-case-in-substitution` refuses a push inside a case inside `"$( )"`.
- `subagent-push`, `subagent-rebase`, and `subagent-absolute-git` refuse publication and integration in a subagent, including after `cd`, past `-C`, and through an absolute path to git.
- `subagent-gh-merge` refuses `gh pr merge` in a subagent.
- `subagent-monitor-push` refuses a push run through the Monitor tool, and `subagent-powershell-escape` one through PowerShell spelled with its backtick escape.
- `subagent-redirected-push`, `subagent-env-split`, and `subagent-subtree-push` refuse a push behind a redirection, inside `env -S'...'`, and through `git subtree push`.
- `subagent-merge-base` and `subagent-tag-list` let a subagent run `git merge-base` and list tags.
- `subagent-local` lets a subagent commit locally, and `subagent-not-git` lets it run a command that is not git.
- `subagent-write` lets a tool that runs no command through, even with git text in its input.
- `owner-push` lets an `autopilot-owner` subagent push its own branch, and `owner-no-verify` refuses it skipping hooks.
- `malformed` refuses an event that is not JSON.
- `project-bunfig` shows the deny holds in a project whose `bunfig.toml` preload prints, when the hook runs with `bun --cwd <kit>` as documented.
- `usage` makes a call without `--claude-hook` a usage error with no decision.

## How to get to it (user POV)

- Not yet: bootstrap does not wire the hook (a pending bootstrap change), so no Claude Code session runs it today. Once wired, any Bash, Monitor, or PowerShell command in Claude Code, in the main session or a subagent, in any permission mode including bypass, runs `bun --cwd <kit> <kit>/agentic/tools/git-guard/cli.ts --claude-hook` with the event on stdin (the entry is in `claude/README.md`).
- A refused command shows the hook's reason as the tool's error, and the command does not run.

## Driving it with verify-kit

Preconditions:

- Drive target: `scripts/verify-kit drive RUN_ID git-guard`.
- Doctor passed. The drive needs nothing optional: no `gh` login, key, or `claude` CLI.

- **Project.** The drive makes a scratch git repository, `git-guard-project/`, whose `bunfig.toml` preloads a script that prints `project preload ran`, and runs every case from it with `bun --cwd <checkout> <checkout>/agentic/tools/git-guard/cli.ts --claude-hook`. A control step runs the hook there without `--cwd` and checks that the preload's line reaches stdout, so the fixture is shown to bite.
- **Main session.** An event without `agent_id` running `git push origin main`: exit 0 and empty stdout. `git commit --allow-empty --no-verify -m probe`, `git commit -nm probe`, `git commit -m "$(cat <<'EOF' ... EOF)" --no-verify` with an apostrophe in the body, and `2>/dev/null git commit -n -m x`: a deny naming skipping git hooks. `git config core.hooksPath .githooks`: a deny saying to ask the user. `git commit -m "docs: explain why --no-verify is refused"`: a deny saying it may only mention the flag and naming `git commit -F <file>`. `git commit -F .git/COMMIT_MSG_DRAFT`: empty stdout. `git commit -m "unterminated`: a deny saying the hook could not read the command. `echo "$(( 1 << 2 ))"`, `printf '{"k":"v"}' | /bin/sh script.sh`, and `case "$v" in *A*) echo a;; *B*) echo b;; esac`: empty stdout. `git -c hook.pre-commit.enabled=false commit -m wip`, `git am -n < 0001-fix.patch`, and `cat <<'EOF' | sh` feeding `git commit -n -m x`: a deny naming skipping git hooks. `git config hook.pre-commit.enabled false` and `git config remove-section hook.lint`: a deny saying to ask the user. `HUSKY=0 git commit -m x`, `export SKIP=lint && git commit -m x`, `HUSKY=0 sh -c 'git commit -m x'`, and PowerShell's `$env:HUSKY = '0'; git commit -m x`: a deny naming a hook manager's skip variable; `SKIP=lint pre-commit run --all-files`: empty stdout.
- **Subagent.** Events with `agent_id` and `agent_type: general-purpose`: `git push origin agent/x`, `cd sub && git -C . rebase origin/main`, `/usr/bin/git push`, and `gh pr merge 28 --squash` are denied as `child publication/integration command: git push`, `git rebase`, `git push`, and `gh pr merge`; the Monitor tool's `git push origin agent/x`, PowerShell's ``git pu`sh origin x``, `>/dev/null git push origin x`, `env -S'git push origin x'`, and `git subtree push --prefix=d origin x` are denied the same way (the last as `git subtree push`); PowerShell's `pwsh -in -c 'git push origin x'` and `echo "${x:-'}"'}" ; command git push origin x ; echo "' #"` are denied as unreadable; `eval git -C repo push origin x`, a push in a case clause after a `# it's ...` comment, `out=$((git push origin agent/x) 2>&1)`, and `echo "$(case $x in a) git push;; esac)"` are denied as `git push`; `printf '%s\n' 'git push origin x' | sh` is denied as unreadable; `git merge-base HEAD origin/main` and `git tag -l` print nothing; `git commit -m local` and `ls -la` print nothing; a Write tool whose content is `git push --no-verify` prints nothing.
- **Owner.** Events with `agent_type: autopilot-owner`: `git push --force-with-lease=agent/x:abc origin agent/x` prints nothing, and `git commit --no-verify -m x` is denied.
- **Malformed.** Stdin `not json`: exit 0 and a deny saying the hook could not read the PreToolUse event.
- **Usage.** No flag: exit 2 and empty stdout.
- **Proof.** Each deny is checked to be exactly `{"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "deny", "permissionDecisionReason": ...}}`, and the scratch repository the cases run in still has no commit afterwards, so the hook ran none of the commands. Evidence: `git-guard/NN-hook-*.txt` with each event on stdin and the hook's output.

## Gotchas

- This drive pipes events to the hook; it does not start Claude Code. That Claude Code honors the deny in bypass-permission mode, sends `agent_id` and `agent_type` from a subagent, and routes Monitor commands through the hook comes from the hooks documentation and headless runs recorded in the pull request that added the hook, not from this drive.
- Claude Code lets a tool call through when a hook cannot start, times out, or exits other than 0 or 2, unless the hook entry sets `"onFailure": "block"` (honored from Claude Code 2.1.295); the documented entry sets it, and this drive does not observe it. Before 2.1.295 the guard fails open on those failures.
- What the guard refuses that it need not (the same list is in ADR 0001 and `claude/README.md`): mentions, because its text patterns see a git command at the start of any line, even in a quoted commit message, a here document, or a search pattern, and the reason then says to commit such a message from a file with `git commit -F <file>` or to search without the leading dashes; a child's harmless uses of a refused subcommand, such as `git rebase --abort`; a skip variable set alone or exported in a command whose git command runs no hooks, such as `export SKIP=lint; git log`; `git config` changes to `core.hooksPath` or any `hook.*` key (git's config-based hooks) for every session, including unsetting `core.hooksPath` (which turns a husky repository's hooks off), which the user makes instead (reading them passes); and any command its reader cannot read: an unclosed quote, substitution, or here document, nesting past 8 levels, a glob or brace in a program name or in git's or gh's subcommand or option words, an `-EncodedCommand` that is not base64 of UTF-16LE, commands fed to a shell (or `Invoke-Expression`) from anything but a here document, a here-string, or `cat <<EOF |`, such as `printf ... | sh`, `curl ... | sh`, `bash <(...)`, or `source <(...)` (a shell given a script operand reads its input as data and passes), a shell started with no input (`bash -l`, `exec zsh`), a single-quoted span holding `}` or `"` inside a double-quoted `${...}` (bash and zsh read it differently), a PowerShell option abbreviation that could name two options (`-in`), a PowerShell value option whose value names `-Command`, `-EncodedCommand`, or `-File` (`-wd /c`), a `wsl` argument holding spaces or quotes without `-e` (wsl joins its words into one line), `wsl -e` running a shell that reads its input, a `[[ ]]` holding a process substitution or `$'...'`, or followed by a redirection, a PowerShell assignment whose value is read as a program, so a quoted value naming a shell (`$m = 'Switch the hook to /bin/sh'`) reads as starting that shell, and an `@"..."@` here-string whose body holds a `"`.
- What the guard does not stop (the same list is in ADR 0001 and `claude/README.md`): commands that appear only after expansion or evaluation: the reader follows common shell syntax, so a command whose program or arguments appear only after expansion or evaluation can get past it (parameter expansion such as `$x push`, arithmetic, brace or glob expansion in git's operands, unusual quoting or syntax forms, shell aliases and functions, git and gh aliases, script files, and programs that run their arguments or input as commands beyond the wrappers it follows, for example `parallel`, `ssh`, `trap`, `xargs git` with the subcommand on stdin, a Python script, or PowerShell's `Start-Process`), and so can other programs that publish (`gh pr create` or `comment`, `gh api`), while anything it cannot read is refused; hooks disabled another way (editing `.git/hooks` or `.git/config`, `GIT_CONFIG_GLOBAL` or `GIT_CONFIG_SYSTEM` pointing at a file, a `GIT_CONFIG_*` variable exported by an earlier command, or a skip variable of a hook manager the guard does not list (it refuses `HUSKY`, `HUSKY_SKIP_HOOKS`, `SKIP`, `PRE_COMMIT_ALLOW_NO_CONFIG`, `LEFTHOOK`, `LEFTHOOK_EXCLUDE`, and `OVERCOMMIT_DISABLE`)); identity it cannot tell in Claude (a nested `claude -p` started from a subagent's shell has no `agent_id` and counts as a main session, a child holding the Agent tool can launch an `autopilot-owner` grandchild, and `agent_id` for teammates is documented but not observed); and MCP tools that run commands. No case here claims otherwise.
- `agent_type` alone does not mark a subagent: Claude Code also sends it for a main session started with `--agent`. The hook treats an event as a subagent's only when it carries `agent_id`.
