# Git guard

Before Claude Code runs a shell command through Bash, Monitor, or PowerShell, agent-kit's PreToolUse hook checks it against the git policy Pi's `git-interceptor` also applies: text patterns that find `git` or `gh`, by name or absolute path, at the start of a line or after `;`, `&`, or `|`, past any assignments that prefix it for that command (`GIT_EDITOR=true git commit`), and do not read the command as a shell would. Any session gets a refusal naming what to do instead for skipping hooks: `--no-verify` after `git` on the same line or on a later line that a quoted string or a line-ending backslash carries the command onto (Claude Code's `git commit -m "$(cat <<'EOF' ... EOF\n)" --no-verify`); `-n` on `git commit` or `git am`, alone or after short flags that take no value (`-an`, `-nm`), but not in a word git refuses as a misspelled long option (`-include`); a hook manager's skip variable (`HUSKY`, `SKIP`, `LEFTHOOK`, and the like) assigned on a line that runs git or on a line of only assignments just before one that starts git; or `core.hooksPath` or a `hook.*` key set or unset with `git -c`, `--config-env`, or `git config`. So does a subagent whose command has a line, or a command after `;`, `&`, or `|`, starting `git push`, `pull`, `merge`, `rebase`, `cherry-pick`, `revert`, `am`, `apply`, or `tag` (except listing or verifying tags), optionally after `git -C <path>`, or `gh pr merge`, unless it runs as an `autopilot-owner`. The main session may publish. An event the hook cannot read is refused rather than let through. Commands the patterns do not match pass, including non-git commands the guard once refused as unreadable (`printf ... | sh`, `bash -l`, an unclosed quote). The patterns also match a mention of a refused command in a quoted message or search; each refusal says how to rephrase one (see Gotchas).

## Sub-features

- `main-push` lets the main session publish.
- `main-no-verify` refuses `--no-verify` in the main session, and `owner-no-verify` refuses it for an `autopilot-owner`.
- `main-mention` refuses a commit message that mentions `--no-verify` with a reason that says it may be a mention and names `git commit -F <file>`; `main-commit-file` lets `git commit -F <file>` through.
- `main-heredoc-no-verify` refuses `--no-verify` on the line after a commit message written in a here document.
- `main-commit-n` refuses `git commit -nm`, and `main-n-mention` refuses a commit message holding `-n` with a reason that says it may be a mention; `owner-commit-n` refuses `-n` for an `autopilot-owner`. `main-flag-message` and `main-long-option-typo` let through commit messages naming `-fno-exceptions` and `-include`, which git would not read as `-n`.
- `main-skip-variable` refuses `HUSKY=0` before `git commit`.
- `main-hooks-override`, `main-hooks-config`, and `main-hooks-unset` refuse `git -c core.hooksPath=...`, `git config core.hooksPath <path>`, and `git config --unset core.hooksPath`; `main-hooks-read`, `main-hooks-read-redirect`, and `main-config-user` let `git config --get core.hooksPath`, `git config core.hooksPath 2>/dev/null || echo unset`, and `git config user.name` through.
- `main-absolute-no-verify` refuses `--no-verify` after `/usr/bin/git`.
- `main-am` and `main-gh-merge` let the main session apply a patch and merge a pull request with `gh`.
- `main-pipe-to-sh`, `main-shell-no-input`, and `main-unclosed-quote` let `printf 'echo hi\n' | sh`, `bash -l`, and `echo "unterminated` through.
- `subagent-push`, `subagent-rebase`, and `subagent-tag` refuse publication and integration in a subagent, including after `cd` and past `-C`.
- `subagent-monitor-push` and `subagent-powershell-push` refuse a push run through the Monitor and PowerShell tools.
- `subagent-mention` refuses a search whose pattern holds `git push` after a `|`, with a reason that says it may be a mention.
- `subagent-gh-merge` refuses `gh pr merge` in a subagent, and `subagent-gh-view` lets it run `gh pr view`.
- `subagent-absolute-push` refuses `/usr/bin/git push` in a subagent.
- `subagent-merge-base`, `subagent-tag-list`, and `subagent-tag-redirect` let a subagent run `git merge-base`, list tags, and list them with `2>/dev/null`.
- `subagent-local` lets a subagent commit locally, and `subagent-not-git` lets it run a command that is not git.
- `subagent-write` lets a tool that runs no command through, even with git text in its input.
- `owner-push` and `owner-gh-merge` let an `autopilot-owner` subagent push its own branch and merge its pull request with `gh`.
- `malformed` refuses an event that is not JSON.
- `project-bunfig` shows the deny holds in a project whose `bunfig.toml` preload prints, when the hook runs with `bun --cwd <kit>` as documented.
- `usage` makes a call without `--claude-hook` a usage error with no decision.

## How to get to it (user POV)

- Not yet: bootstrap does not wire the hook (a pending bootstrap change), so no Claude Code session runs it today. Once wired, any Bash, Monitor, or PowerShell command in Claude Code, in the main session or a subagent, in any permission mode including bypass, runs `bun --cwd <kit> <kit>/agentic/tools/git-guard/cli.ts --claude-hook` with the event on stdin (the entry is in `claude/README.md`).
- A refused command shows the hook's reason as the tool's error, and the command does not run.

## Driving it with verify-kit

Preconditions:

- Drive target: `scripts/verify-kit drive RUN_ID git-guard`.
- Doctor passed. The drive needs nothing optional: no `gh` login, key, or `claude` CLI.

- **Project.** The drive makes a scratch git repository, `git-guard-project/`, whose `bunfig.toml` preloads a script that prints `project preload ran`, and runs every case from it with `bun --cwd <checkout> <checkout>/agentic/tools/git-guard/cli.ts --claude-hook`. A control step runs the hook there without `--cwd` and checks that the preload's line reaches stdout, so the fixture is shown to bite.
- **Main session.** An event without `agent_id` running `git push origin main`: exit 0 and empty stdout. `git commit --allow-empty --no-verify -m probe`: a deny naming skipping git hooks. `git commit -m "docs: explain why --no-verify is refused"`: a deny saying the text may only mention the flag and naming `git commit -F <file>`. `git commit --allow-empty -nm probe`: a deny naming skipping git hooks with `-n`. `git commit -m "fix -n handling"`: the same deny, saying the text may only mention the flag and naming `git commit -F <file>`. `git commit -m "$(cat <<'EOF'\nDon't skip hooks\nEOF\n)" --no-verify`: a deny naming skipping git hooks with `--no-verify`. `HUSKY=0 git commit --allow-empty -m probe`: a deny naming a hook manager's skip variable. `git -c core.hooksPath=/dev/null commit --allow-empty -m probe`, `git config core.hooksPath /dev/null`, and `git config --unset core.hooksPath`: a deny naming core.hooksPath or a hook.* key. `/usr/bin/git commit --allow-empty --no-verify -m probe`: a deny naming skipping git hooks. `git commit -F .git/COMMIT_MSG_DRAFT`, `git commit -m "Build with -fno-exceptions"`, `git commit -m "Pass -include to clang"`, `git config --get core.hooksPath`, `git config core.hooksPath 2>/dev/null || echo unset`, `git config user.name probe`, `git am patch`, `gh pr merge 3 --squash`, `printf 'echo hi\n' | sh`, `bash -l`, and `echo "unterminated`: empty stdout.
- **Subagent.** Events with `agent_id` and `agent_type: general-purpose`: `git push origin agent/x`, `cd sub && git -C . rebase origin/main`, and `git tag v1` are denied as `child publication/integration command: git push`, `git rebase`, and `git tag`; the Monitor and PowerShell tools' `git push origin agent/x` are denied the same way; `rg "error|git push" docs/` is denied as `git push` with a reason saying the text may only mention the command; `gh pr merge 3 --squash` is denied as `gh pr merge` with a reason saying to search without `gh` in front; `/usr/bin/git push origin agent/x` is denied as `git push`; `gh pr view 3`, `git merge-base HEAD origin/main`, `git tag -l`, `git tag 2>/dev/null`, `git commit -m local`, and `ls -la` print nothing; a Write tool whose content is `git push --no-verify` prints nothing.
- **Owner.** Events with `agent_type: autopilot-owner`: `git push --force-with-lease=agent/x:abc origin agent/x` and `gh pr merge 3 --squash` print nothing, and `git commit --no-verify -m x` and `git commit -nm x` are denied.
- **Malformed.** Stdin `not json`: exit 0 and a deny saying the hook could not read the PreToolUse event.
- **Usage.** No flag: exit 2 and empty stdout.
- **Proof.** Each deny is checked to be exactly `{"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "deny", "permissionDecisionReason": ...}}`, and the scratch repository the cases run in still has no commit and an unchanged `.git/config` afterwards, so the hook ran none of the commands. Evidence: `git-guard/NN-hook-*.txt` with each event on stdin and the hook's output.

## Gotchas

- This drive pipes events to the hook; it does not start Claude Code. That Claude Code honors the deny in bypass-permission mode, sends `agent_id` and `agent_type` from a subagent, and routes Monitor commands through the hook comes from the hooks documentation and headless runs recorded in the pull request that added the hook, not from this drive.
- Claude Code lets a tool call through when a hook cannot start, times out, or exits other than 0 or 2, unless the hook entry sets `"onFailure": "block"` (honored from Claude Code 2.1.295); the documented entry sets it, and this drive does not observe it. Before 2.1.295 the guard fails open on those failures.
- What the guard refuses that it need not (the same list is in ADR 0001 and `claude/README.md`): mentions, because its patterns see a git command at the start of any line or after `;`, `&`, or `|`, even in a quoted commit message, a here document, or a search pattern, `--no-verify` anywhere in a quoted message or here document that spans lines after `git` (including a `gh pr create --body` after `git push` on the same command, whose reason also names `--body-file`), and a word git would read as `-n` anywhere in a `git commit` or `git am` command before its next `;`, `&`, or `|`, and the reason then says to commit such a message from a file with `git commit -F <file>` or to search without the leading dashes or without `git` or `gh` in front; a skip variable assigned for another command on a line that also runs git (`SKIP=1 make && git status`); and a child's harmless uses of a refused subcommand, such as `git rebase --abort`.
- What the guard does not stop (the same list is in ADR 0001 and `claude/README.md`): a git or gh command the patterns do not see in the text (one not at the start of a line or after `;`, `&`, or `|`, such as after leading spaces, by a path that does not start with `/` such as `./git` or `~/bin/git`, by a name with an extension such as `git.exe push`, after a redirection, a keyword, or an assignment whose quoted value spans lines, inside a wrapper such as `command`, `env`, `sh -c`, `eval`, or `xargs`, a subshell or substitution, PowerShell's call operator or backtick escapes; git options before the subcommand other than `-C`, with `-c` and `--config-env` read only for hook keys; `--no-verify` on a later line that the command reaches another way, such as an unquoted `$(...)` spanning lines or a here document inside a quoted string that holds an unpaired double quote; shell aliases and functions, git and gh aliases, and script files); hooks skipped another way (a prefix of `--no-verify`, `-n` after a quoted `;`, `&`, or `|` in its `git commit` command or on a later line than its `git commit`, a `GIT_CONFIG_*` variable carrying a hook key, a skip variable set through a wrapper, set on an earlier line unless that line holds only assignments and the next line starts with git, or set the PowerShell way (`$env:HUSKY = '0'; git commit`, `Set-Item env:HUSKY 0; git commit`), and editing `.git/hooks` or `.git/config`); other programs that publish (`git send-pack`, `git http-push`, `git subtree push`, `pull`, or `merge`, `gh pr create` or `comment`, and `gh api`); identity it cannot tell in Claude (a nested `claude -p` started from a subagent's shell has no `agent_id` and counts as a main session, a child holding the Agent tool can launch an `autopilot-owner` grandchild, and `agent_id` for teammates is documented but not observed); and MCP tools that run commands. No case here claims otherwise.
- `agent_type` alone does not mark a subagent: Claude Code also sends it for a main session started with `--agent`. The hook treats an event as a subagent's only when it carries `agent_id`.
